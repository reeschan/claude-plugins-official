# 観点: 規約と仕様

リポジトリの規約・渡された追加の規約・仕様に、変更された行が反していないかを見る。いつも当てる。

## 見るもの

- 変更された行が、そのファイルに当たる `CLAUDE.md`・`AGENTS.md` の決まりに反する。当たるのは、同じフォルダか親のフォルダにある規約だけ。
- 渡された追加の規約 (`--rules`、`Rules:`) に反する。
- 渡された仕様 (`--spec`、`Spec:`) と食い違う。仕様が決めていない振る舞いを、変更が勝手に決めている。
- 規約に書かれた UI の決まり (アクセシビリティ、既定の見た目、内部リンクの書き方) に反する。
- 規約が無くても、変更が足した UI 部品について次の 2 つは出す: 入力欄に名前 (`label`・`aria-label`) が無い、`outline: none` などで focus の表示を消して代わりが無い。それ以外の見た目は、規約に書かれていなければ見ない。
- 決定の記録 (ADR) と食い違う。決定の記録は、リポジトリの decisions・adr などのフォルダにあるものだけ。

## 確かめ方

- 反している決まりの文を引用できること。引用は原文のまま、出どころ (ファイル名と見出し) を添える。
- その規約がこのファイルに当たること (フォルダの位置、規約に書かれた対象)。
- コードで明示的に黙らせていないこと (lint の無視コメント、規約が認める例外の印)。

## この観点で出さないもの

- 規約に書かれていない好み。
- 規約が勧めているだけ (必須ではない) で、変更の理由が読み取れるもの。
- 規約の文を引用できないもの。ただし「見るもの」で規約が無くても出すとした 2 つ (入力欄の名前、focus の表示) は除く。
