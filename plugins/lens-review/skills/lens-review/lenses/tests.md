# 観点: テスト

変更されたテストが、守るべきことを本当に確かめているかを見る。テストのファイルの変更があるときに当てる。

## 見るもの

- 実装を壊してもテストが通る: 早い return、条件付きの `skip`、比較する値の取り違え、例外を飲み込む `try`、常に真になる assert。
- 追跡されていない fixture や、手元にしか無いファイル・環境変数に頼っている。
- 実際の運用と違う引数・設定で呼んでいて、対象の経路を通らない。
- テストの名前や説明が言う振る舞いと、assert が確かめている振る舞いが違う。
- 本物の外部 (本番の API、実在の環境) に届く。

## 確かめ方

- 実装を 1 か所壊した写しを一時フォルダに作り、テストが落ちるかを見る (リポジトリの中は変えない)。
- fixture のパスを `git ls-files` と `git check-ignore -v` にかける。
- テストが呼ぶ引数を、本番の呼び出し元の引数と並べる。

## この観点で出さないもの

- 「テストが足りない」「網羅率が低い」だけの指摘。
- テストの書き方の好み (名前、並べ方、ヘルパーの切り出し)。
