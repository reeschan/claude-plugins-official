# 観点: ロジック

入力によらず誤る処理と、境界・一致条件・集計の誤りを見る。コードの変更があるときに当てる。

## 見るもの

- 構文・型・import・未定義の参照で、動かない。
- 入力によらず結果が誤る: 条件の向き、off-by-one、戻り値の取り違え、引数の順の取り違え。
- 空・1 件・全件除外・逆順で振る舞いが変わる。「空」と「未指定」を同じ真偽値で判定している。
- 作る側と使う側で、キー・ファイル名・イベント名・フィールド名が合っていない。
- 部分一致・前方一致・正規表現・glob が、意図より広いか狭い (例えば `item-1` が `item-10` にも当たる)。
- 予約した名前 (集計用のキーなど) と利用者が付けた名前、別の名前空間の同じ id が衝突する。
- 値が無いとき `None == None`・`undefined === undefined` で「一致」とみなす。
- 「すべての要素で」確かめるべき条件を「どれか 1 つで」判定している、またはその逆。
- イベントや行を読む順によって、後の値が先の値を上書きする向きが変わる。
- 単位 (実行先とモデル、ファイルとフォルダ、ユーザーと組織) を取り違えて、除外や許可が広すぎる・狭すぎる。
- 合計・件数・金額・時間が、対象を落とす、二重に数える、単位を取り違える。例外の経路で値が 0 や初期値に戻る。
- ハッシュ・キャッシュの鍵・署名を、最終の形になる前の値で計算している。

## 確かめ方

- 境界の入力 (空、1 件、最大、逆順) を 1 つ作って実行する。
- パターンには「当たるべき例」と「当たってはいけない例」を 1 つずつ渡して結果を見る。
- 作る側と使う側を `rg` で両方開き、名前と形を並べる。
- 外部 API の単位・形は、公式の文書の該当箇所を引く。引けなければ要確認にする。

## この観点で出さないもの

- 読みやすさ、命名、もっと良い書き方の提案。
- 型検査やコンパイラが拾うだけのもの (実行時に誤る経路がないもの)。
