# 観点: 文字列による判定

文字列が現れたことを事実の根拠にする判定と、手書きのテキストの解析を見る。コードの変更で、文字列の照合 (正規表現・`in`・`includes`・`startswith`) やテキストの解析 (行や見出しで分ける、フェンスを数える) を足したか変えたときに当てる。

## 見るもの

- 語が現れたことを、実行した・呼んだ・合格した根拠にする。例えば、コマンドの文字列がログのどこかにあれば「実行した」、ツールの名前が本文にあれば「呼んだ」とみなす。説明文・引用・コメント・失敗のメッセージに同じ語があっても当たる。
- 印 (分類の札、状態の語、エラーの語) を、決めた節や欄の外からも拾う。広い語 (`error`、`authentication` など) が、関係の無い行にも当たる。
- 手書きの Markdown の解析が、CommonMark の決まりと違う:
  - フェンスの開きを数えずに閉じを受け付ける。
  - 閉じのフェンスを開きと同じ長さに限る (長い閉じも有効)。
  - `~~~` やインデントしたフェンスを見ない。
  - フェンスの中の `#` を見出しとして扱う。
- 行の分け方が書く側と違う。例えば、書く側は `\n` で区切るのに、読む側が `splitlines()` で `\u2028` や `\r` でも分ける。
- コマンドの行を文字列の前方一致で見分ける。前に付く環境変数・`cd ... &&`・シェルの違い (`bash -lc`) で当たらなくなる。

## 確かめ方

- 照合の行ごとに、当たるべき例と、当たってはいけない例 (同じ語を含む説明文・失敗のメッセージ・長い id) を 1 つずつ作って渡す。
- テキストの解析には、長いフェンス・`~~~`・フェンスの中の見出し・閉じの無いフェンスを含む入力を渡し、結果を見る。
- 書く側の出力をそのまま読む側に渡して、往復で同じものに戻るかを見る。

## この観点で出さないもの

- glob・正規表現の一致の広さで、根拠の判定にも解析にも関わらないもの (ロジックで見る)。
- 外から来る文字列でパス・URL・コマンドを組み立てる境界越え (入力と失敗で見る)。
- 構造化した出力 (JSON・終了コード) が使えるのに、文字列で判定していること自体の好み。実害の経路を書けないもの。
