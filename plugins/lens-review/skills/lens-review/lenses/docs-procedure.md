# 観点: 文書と手順

文書・エージェントが読むスキル本文・設定ファイルが、実装やほかの文書と食い違っていないか、書かれた手順がそのまま通るかを見る。`.md`・`.d2`・設定ファイルの変更があるときに当てる。

## 見るもの

- 文書が名指しする関数・フラグ・ファイル・数値・手順の順が、実際のコードや同じリポジトリの別の文書と合わない。
- 方式を変えた後に、古い方式の記述が残っている (変更したファイル以外にも)。
- 載っているコマンドを写して実行すると失敗する: 必須の引数が足りない、前提のフォルダが無い、`<名前>` がシェルのリダイレクトになる、OS によって書き方が違う。
- 手順を上から実行したとき、ある分岐で要る入力 (回答・承認・設定値・ファイル) がまだ作られていない。
- 設定の組み合わせ (off・auto・名前付き、通常・ヘッドレス・再開) によって、手順が通らない、どの分岐にも当たらない、2 つの分岐に同時に当たる。
- 手順が求める動作と、実行者の権限が両立しない (例えば読み取り専用の実行者に結果ファイルを書かせる)。
- 「作った人と別の人が確かめる」などの不変条件を、設定の組み合わせが破る。

エージェントが読むスキル本文 (`SKILL.md`、prompts、付録) では、分岐 (上から 4・5 つ目) と権限 (6・7 つ目) を先に見る。読んだエージェントがそのまま実行するので、食い違いがそのまま誤動作になる。

## 確かめ方

- 文書の中の識別子とコマンドを `rg -n` で実在確認する。
- コマンドは `--help` か dry-run で実行し、`argparse` などの必須引数と突き合わせる。
- 手順を実行順に並べ、各ステップの入力が「どこで作られるか」を表にして、作られる前に使っていないかを見る。
- 同じ話題を書いた別の文書 (README の各言語版、仕様と ADR、表と図) を `rg` で探し、揃っているかを見る。

## この観点で出さないもの

- 言い回し、誤字、文体、見出しの付け方。
- 作業記録や検証記録 (PBI の記録など) の体裁。
- 実装と照らし合わせられない一般的な説明の不足。
