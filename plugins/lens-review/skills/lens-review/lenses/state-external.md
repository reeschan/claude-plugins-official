# 観点: 状態と外部

書き込みの順と途中の失敗、並行実行、外部呼び出し、残る状態、OS と文字コードの差を見る。コードの変更があるときに当てる。

## 見るもの

- 「消してから作る」「2 つのファイルを別々に書く」など、途中で止まると壊れた状態や半端なファイルが残る。
- 利用者の設定や未コミットの変更を、確認も退避もなく上書き・削除する。
- 処理が終わる前に「完了」を記録している。完了の報告を作る前に状態を進めている。
- 読む → 待つ → 書く の間に、別の実行が割り込める (複数プロセス、複数タブ、ロックの取り直し、再入)。
- 外部の呼び出し (`subprocess`、`fetch`、`urlopen`、HTTP クライアント) に待ち時間の上限が無い。上限を超えたときに子プロセスを止めていない。ロックを持ったまま外部を待つ。
- 呼ばれる側が、親の環境 (`GIT_DIR`、git の hooks、プロキシ、作業フォルダ) を意図せず継ぐ。
- 前の実行の状態 (キャッシュ、ラッチ、残ったファイル、モジュールの変数) が、新しい実行の前提と合わない。再描画や再実行が入力途中の値を消す。
- 例外の文言・トレース・ログに、伏せるべき本文 (応答の抜粋、鍵、個人の情報) がそのまま流れる。ほかの経路では伏せているのに、1 つの経路だけ伏せていない。
- 権限の境界を越えて内部のオブジェクトを渡す (Electron の preload・`contextBridge` が `ipcRenderer` などを戻り値で返す、サーバーの内部の型をそのまま API で返す)。
- 旧い形式 (旧キー・旧版のファイル) で残ったデータを、新しい読み手が黙って飛ばす。
- 複数の利用者 (テンプレート・設定の層) が共有するファイルを、1 つの利用者の設定で上書きする。
- 「消す → 移す → 印を書く」の途中で止まると、古い印と新しい中身が組になって有効に見える。
- 計測が無くても回数や計算量で示せる重さ: キー入力のたびに設定ファイル全体を同期で書く、ループの中で毎回全件を並べ替える・走査する。
- OS・文字コードの差で動かない: Windows のパスの区切りとドライブ名、PowerShell 5.1 の既定の文字コード、改行、UTF-8 を途中で切る読み取り。

## 確かめ方

- 書き込みの各行の直後で例外が出たら何が残るかを、行ごとに追う。安くできるなら失敗を注入して実行する。
- 外部を呼ぶ行を `rg -n 'subprocess|Popen|fetch\(|urlopen|requests\.|axios'` で集め、上限と後始末を見る。
- 競合は、起きる順序を「A が読む → B が書く → A が書く」の形で具体的に書けること。
- OS の差は、対象の OS で動かす予定があること (README・CI・スクリプトの拡張子) を確かめる。

## この観点で出さないもの

- 起きる順序を具体的に書けない競合。
- 対象の OS で動かす予定が無いと分かるもの。
- 回数や計算量でも示せない性能の好み。
